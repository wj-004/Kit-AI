# Planificación del proyecto

Trabajar con solicitudes, fuentes y decisiones confirmadas. Conservar IDs, criterios, dependencias y evidencia; las propuestas requieren autorización para ejecutarse.

Leer las fuentes y requerimientos originales durante el relevamiento e incorporar sus reglas y criterios al plan. Después, usar el plan como referencia de ejecución; releer los originales solo por pedido expreso del usuario. Consultar las dudas que el plan no resuelva.

- Preparar un proyecto: consultar [preparación inicial](references/flujo-de-trabajo.md#preparación-inicial), incluidas fuentes y stack pendientes.
- Crear o reorganizar el plan: usar las plantillas y el [esquema](references/plan-schema.md); sus catorce campos siguen siendo obligatorios.
- Retomar con información insuficiente: consultar [reanudación](references/flujo-de-trabajo.md#reanudación) y contrastar solo los cambios pertinentes.

Para una tarea existente, el contexto de `roadmap.py task ID` y las instrucciones del proyecto son suficientes si no aparecen contradicciones. Actualizar los campos que cambiaron y guardar evidencia breve. Las decisiones materiales y los informes extensos se enlazan desde su ubicación, sin duplicarlos en la tarea.
